🎮 Arena — Overall Architecture, Workflow, Rules & Logic
1. Feature Overview
Arena is a standalone competitive gamification feature where employees can compete in short knowledge-based battles.
The Arena is independent from Skill Intelligence, Skill Gap Analysis, and Assessment scoring.
Arena results affect only:
•	Arena Points
•	Arena Rating
•	Arena Wins/Losses/Draws
•	Win Streak
•	Arena Badges
•	Arena Leaderboard
Arena must not modify:
•	XP
•	Skill Gap
•	Assessment Score
•	Competency Score
•	Employee Skill Profile
________________________________________
2. Core Game Modes
Human vs Human
Two real employees compete in a real-time Arena battle.
Requirements:
•	Both users must be authenticated.
•	Both must be online.
•	Both must be available for Arena.
•	Players must be compatible according to matchmaking rules.
•	Opponent must explicitly accept the challenge.
•	Server controls the match state, timer, answers, scores, and final result.
Human vs AI
AI is used as a fallback when no suitable human opponent is available.
AI Battle is still an online mode because:
•	Questions may be generated by the backend/AI service.
•	The backend controls the game.
•	Results are stored in the database.
AI Battle has reduced Arena Point rewards compared with Human vs Human.

8. Nearby Matchmaking
The browser requests location permission.
The client provides approximate latitude/longitude to the backend.
The backend:
1.	Stores/uses the location securely.
2.	Finds users currently available for Arena.
3.	Calculates approximate distance.
4.	Filters compatible players.
5.	Selects an eligible opponent.
The exact location must never be exposed to another employee.
The opponent may see:
🟢 Rahul
Nearby
Available
Optionally:
~800 m away
Never expose exact coordinates.

9. Player Availability States
OFFLINE
   ↓
ONLINE
   ↓
ARENA_AVAILABLE
   ↓
SEARCHING
   ↓
CHALLENGE_PENDING
   ↓
IN_MATCH
   ↓
ARENA_AVAILABLE
Rules:
•	OFFLINE → cannot receive challenges.
•	ONLINE → can browse Arena.
•	ARENA_AVAILABLE → eligible for matchmaking.
•	SEARCHING → actively looking for an opponent.
•	CHALLENGE_PENDING → temporarily unavailable for another challenge.
•	IN_MATCH → cannot receive another challenge.
•	After match completion → return to ARENA_AVAILABLE.

11. Battle Rules
Each match contains:
5 Questions
15 seconds per question
Both players receive the same question.
Question
   ↓
15-second timer
   ↓
Player submits answer
   ↓
Answer locked
   ↓
Server validates
   ↓
Calculate points
   ↓
Next question
The server controls:
•	Question order
•	Timer
•	Answer validation
•	Score
•	Match state
•	Final winner
The frontend must never be trusted to determine the final score or winner.
________________________________________
12. Question Generation
Before the battle begins:
Match Created
     ↓
Generate / select 5 questions
     ↓
Validate questions
     ↓
Store match questions
     ↓
Start Battle
Both players receive the same questions.
Questions should be relevant to the selected Arena topic/designation when applicable.
Do not generate a new AI question separately for each player during the battle.

13. Scoring
The Arena battle score determines the winner.
Example:
Player A
Correct: 4
Score: 380

Player B
Correct: 3
Score: 290

Winner → Player A
The scoring algorithm may consider:
•	Correct answer
•	Response time
The exact scoring formula must be implemented on the server.
________________________________________
14. Match Result Rules
Human vs Human
Winner → +50 Arena Points
Loser  → -30 Arena Points
Draw   → +0 Arena Points
Example:
Player A = 450 AP
Player B = 500 AP

A wins
↓
A = 500 AP
B = 470 AP
Arena Points must never affect XP.
________________________________________
15. AI Battle Rules
AI is used when no suitable human opponent is available.
AI Win  → +10 Arena Points
AI Loss → -10 Arena Points
AI Draw → +0 Arena Points
AI matches should have reduced competitive impact compared with Human vs Human.
AI matches should not be treated as equivalent to Human vs Human for competitive achievements/rating unless explicitly configured.
The AI should behave like a reasonable opponent rather than always answering instantly and perfectly.
AI difficulty should be configurable.
________________________________________
16. XP Rules
Arena does not modify XP.
Human Win → XP unchanged
Human Loss → XP unchanged
Human Draw → XP unchanged

AI Win → XP unchanged
AI Loss → XP unchanged
AI Draw → XP unchanged
Arena is completely separate from the platform XP system.
________________________________________
17. Arena Rating
Arena Rating is separate from Arena Points.
Arena Points
    ↓
Leaderboard position

Arena Rating
    ↓
Matchmaking strength
Arena Rating is used to find reasonably competitive opponents.
Arena Rating should not be treated as the leaderboard score.
The exact rating algorithm can be implemented later using an Elo-style or similar rating system.
________________________________________
18. Win Streak
Win streak tracks consecutive Arena victories.
Example:
Win → Streak 1
Win → Streak 2
Win → Streak 3
Loss → Streak 0
Draw behavior:
Draw → Streak unchanged
AI wins should not automatically count toward the competitive human win streak unless explicitly configured.
Recommended:
Competitive win streak = Human vs Human wins only.
________________________________________
19. Arena Badges
Initial badges:
⚔️ First Blood
Unlock after first Human vs Human victory.
🏆 5 Wins
Unlock after 5 Human vs Human victories.
🔥 10 Win Streak
Unlock after achieving a 10-match consecutive Human vs Human win streak.
👑 Arena Champion
Unlock for finishing #1 on the Arena Leaderboard according to the defined leaderboard period.
Badges are permanent once unlocked unless the product later introduces seasonal badges.

25. Disconnect Rules
If a player disconnects during matchmaking:
Remove from matchmaking queue
If a player disconnects after the match starts:
Start reconnection window
        ↓
Player reconnects?
   ├── YES → Continue
   └── NO → Match forfeiture
The exact forfeiture policy should be configurable.
Do not immediately declare a winner because of a temporary network interruption.
________________________________________
26. Duplicate Match Prevention
The backend must prevent:
User A
   ↓
Match 1
   ↓
User A tries to start Match 2
Server response:
Already in an active Arena match.
A user can have only one active Arena match at a time.

Frontend Arena Points

Timestamp / response information
The server determines:
Correctness
Response time
Score
Winner
Arena Points
Rating

29. Important Business Rules
1.	Arena is independent of Skill Intelligence.
2.	Arena does not change XP.
3.	Arena does not change assessment scores.
4.	Arena does not change skill-gap data.
5.	Human battles are the primary competitive mode.
6.	AI is a fallback when suitable humans are unavailable.
7.	Human Win = +50 AP.
8.	Human Loss = -30 AP.
9.	Human Draw = 0 AP.
10.	AI Win = +10 AP.
11.	AI Loss = -10 AP.
12.	AI Draw = 0 AP.
13.	Leaderboard ranks users by Arena Points.
14.	Arena Rating is separate from Arena Points.
15.	Badges appear on the user's profile.
16.	Exact employee location is never exposed.
17.	A player cannot participate in multiple active matches.
18.	Server is authoritative for game state and rewards.
19.	Challenge requires explicit opponent acceptance.
20.	Temporary network disconnects must have reconnection handling.

32. Product Principle
The Arena should always follow this principle:
Human-first → Competitive → Fair → Real-time → AI fallback
The Arena exists to create healthy competitive engagement while remaining completely separate from official employee competency assessment and Skill Intelligence data.
